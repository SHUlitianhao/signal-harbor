# Signal Harbor PRD v1.3

## 文档信息

- 类型：产品需求文档与总体方案
- 日期：2026-05-10
- 适用范围：单用户、本机自托管、Windows/WSL 常驻、本机后端 + Android 手机 PWA
- 当前节点：RSSHub 首批来源、手机远程闭环、事件归并、数据源管理、版本展示和数据保留说明已进入 MVP。

## 一句话定义

Signal Harbor 是运行在本机的投资与国际资讯情报收集器，用于采集公开来源，完成标准化、去重、分析、搜索、收藏、提醒、事件归并和手机端查看；它只辅助研究，不输出直接买卖建议。

## 1. 目标与非目标

### 目标

- 持续采集投资与国际资讯相关内容。
- 通过 RSSHub 扩展公开信息源，消费公开 RSS route。
- 将内容标准化为本地可搜索、可收藏、可提醒、可归并的情报库。
- 支持手机 PWA 在局域网或受保护远程入口下独立浏览。
- 保留原始 URL、来源名称、发布时间和证据引用。
- 采用模块化、可插拔、渐进扩展的架构。

### 非目标

- 不做自动交易、券商账户联动或直接买卖指令。
- 不做多用户 SaaS。
- 不承诺高风控平台稳定采集。
- 不把未加保护的 HTTP 服务暴露到公网。
- 不把 RSSHub 的 Node/TypeScript 依赖并入 Signal Harbor Python 后端。
- 不在当前阶段接入外部翻译 API、云模型、embedding 或语义向量库。

## 2. 用户与核心场景

- 目标用户：单个研究型用户，需要长期跟踪股票、行业、国家、事件或舆情线索。
- 场景 A：主题持续跟踪，在异常变化时收到提醒。
- 场景 B：碎片信息整合，把多来源信息沉淀为可搜索证据库。
- 场景 C：手机远程查看，在外部网络中通过受保护入口浏览最新流、事件、提醒和搜索结果。
- 场景 D：研究沉淀，把线索保存到收藏、专题、观察清单和保存搜索。

## 3. 产品原则

- 单用户优先。
- 稳定优先，先保证主链路，再扩展来源。
- 证据优先，摘要和评分必须可追溯。
- 噪音可控，重复事件合并展示。
- 本地优先，外部能力可选接入。
- 安全访问优先，手机远程访问必须经过认证和安全通道。

## 4. 当前功能需求

### 4.1 公开源采集

当前支持：

- RSS、RSSHub、JSON、低风险静态 HTML 和 fixture。
- 每个来源可配置名称、类型、地址、标签、启用状态、发布机构、地区、市场、语言、质量层级、默认主题、include/exclude 关键词。
- RSSHub 来源通过 `rsshub_base_url` + `rsshub_route` 生成最终 RSS URL，并可检查 `/healthz`。
- HTML/JSON 来源需要 mapping；手机端新增 JSON/HTML 若缺少 mapping，仅作为目录说明，不参与采集。
- 单个来源失败写入 TaskRun，不影响其他来源。

边界：

- 只接入公开、无需登录、无需 Cookie、无需验证码、无需 JS 渲染、无需浏览器自动化、无需规避反爬的来源。
- 401/403/429 或明显阻止自动访问的 route 应停用或只保留配置能力。

### 4.2 RSSHub 适配

当前首批 route：

- 华尔街见闻重要快讯：`/wallstreetcn/live/global/2`
- 财联社加红电报：`/cls/telegraph/red`
- 金十重要快讯：`/jin10/important`
- 同花顺重要要闻：`/10jqka/realtimenews/重要`
- DW 中文国际新闻：`/dw/rss/rss-chi-all`

要求：

- Signal Harbor 不修改 RSSHub 项目源码。
- RSSHub 运行、Node 依赖、Redis 缓存和 route 维护由 RSSHub 自身承担。
- PWA 数据源页应展示 RSSHub base、route、质量层级、过滤摘要和最近失败信息。

### 4.3 分析与翻译

当前支持：

- 规则摘要、实体提取、风险词提取、规则评分。
- 本地词典英译中，默认中文优先展示标题、摘要、标签和风险提示。
- 原文标题、正文、来源 URL 和证据引用必须保留。
- 词典状态、词典 CRUD 和批量补翻译 API 作为 internal maintenance 保留，PWA 不展示普通翻译维护模块。

边界：

- 当前不是完整机器翻译，不做长文全文翻译。
- 后续翻译增强优先接本地大模型自动翻译 provider。

### 4.4 同一事件归并

目标：多个来源报道同一事件时合并展示，减少最新流和提醒重复刷屏。

当前 MVP：

- 完全重复仍由 `canonical_hash` 入库去重。
- 相似事件归并只做运行时计算，不新增事件表。
- 归并依据：标题相似、实体/标签重叠、发布时间相近。
- 冲突保护：明显相反动作词不归并。
- 最新流、搜索、详情、提醒和事件页返回事件字段、相关报道、来源数和证据引用。
- 归并解释字段包括 `event_merge_reason`、`matched_tokens`、`matched_topics`、`time_window`、`conflict_guard`。

边界：

- 不接 embedding、向量数据库、外部大模型或云模型做语义事件判断。
- 可能漏合并或误合并，不能作为长期事件档案。

### 4.5 搜索、收藏与专题

要求：

- 搜索支持关键词、来源、主题、分数、收藏、时间和翻译状态。
- 支持保存搜索、收藏、观察清单和专题集合。
- 从最新流、搜索、收藏、专题和提醒进入详情时行为一致。

### 4.6 手机 PWA

页面范围：

- 最新、事件、数据源、搜索、专题、提醒、运行。

要求：

- 左上角常驻显示非敏感版本号。
- 手机窄屏下按钮、长标题、来源标签和提醒文本不溢出。
- API 失败、离线、认证失败、后端未启动时显示可理解状态。
- service worker 只缓存静态 shell，不缓存 `/api/` 数据。

### 4.7 手机远程访问

要求：

- 后端仍运行在用户本机。
- 手机通过浏览器/PWA 使用服务。
- 局域网访问只适合可信网络。
- 受保护远程访问必须依赖 VPN、安全隧道、零信任网络或反向代理，并启用 Basic Auth 或等价保护。
- 不提供裸公网暴露步骤，不保存真实密码、token、Cookie 或隧道地址。

### 4.8 提醒与运行

要求：

- AlertRule 可按关键词和分数触发站内消息。
- 情报类消息可打开详情，系统消息有可读降级说明。
- 同一事件多来源命中时按事件降噪。
- 运行页展示健康、远程访问、调度器、最近 TaskRun 和手动公开源采集按钮。

## 5. 数据对象

核心对象：

- `Source`：来源配置和元数据。
- `Item`：标准化情报，保留原文、来源、发布时间、语言、翻译和搜索字段。
- `Insight`：摘要、评分、风险词和证据引用。
- `Extraction`：实体、风险词、翻译等可追溯处理结果。
- `Watchlist` / `Collection` / `Favorite` / `SavedSearch`：研究沉淀。
- `AlertRule` / `Notification`：提醒规则与站内消息。
- `TaskRun`：采集和处理任务记录。

数据保留：

- 默认不自动删除 `Item`、`Insight`、`Extraction`、`Asset`、收藏、专题、TaskRun 或 Notification。
- 清理脚本默认 dry-run，只可显式清理旧 TaskRun 和 Notification，不删除情报 Item 和证据 URL。
- 同事件归并不删除任何原始 Item。

## 6. 架构边界

- SourceAdapter 负责不同来源采集。
- Extractor 负责正文、OCR、字幕、转写等提取。
- ModelProvider / TranslationProvider 负责可插拔分析和翻译。
- Scorer 负责高价值信息评分。
- Notifier 负责站内消息和未来外部推送。
- API 与 PWA 保持单用户、本机自托管形态。

## 7. 验收标准

- 本机服务可启动并通过 `python3 scripts/check.py`。
- 手机可通过本机、局域网或受保护远程入口查看 PWA。
- RSSHub 首批公开来源可进入采集、过滤、去重、分析、搜索和最新流。
- 新增 RSS/RSSHub 来源后可通过运行页公开源采集入库。
- JSON/HTML 缺少 mapping 时不被误认为可采集。
- 英文公开源默认中文优先展示，同时保留原文和证据。
- 同一事件多来源报道能合并展示，并保留每条原始 URL。
- 提醒页可打开关联情报，系统消息有降级说明。
- 页面左上角版本号可用于截图对比和远程排障。

## 8. 风险与后续建议

- 高风控平台采集稳定性和维护成本高，应先做风险设计再接入。
- 信息量扩大后需要 RSSHub 状态诊断、来源质量分层和更细过滤策略。
- 事件归并规则可能漏合并或误合并，后续可增加可选语义索引接口。
- 翻译体验应优先接本地大模型自动翻译，而不是恢复手工词典维护页面。
- 后续可拆分 `sqlite.py`、`app.js`、`public_sources.py`，降低单文件上下文成本。
