# Signal Harbor 路线图

本文件只保留当前阶段判断和下一步任务。历史执行细节不再展开，避免后续 agent 反复读取长 goal 文本；当前状态先读 `docs/CURRENT_STATE.md`。

## 1. 当前节点

已完成可运行 MVP：

- Python 标准库后端、SQLite、本地 REST API、静态 PWA。
- SourceAdapter：fixture、RSS、RSSHub、JSON、低风险静态 HTML。
- RSSHub 首批真实 route：华尔街见闻重要快讯、财联社加红电报、金十重要快讯、同花顺重要要闻、DW 中文国际新闻。
- 采集、标准化、源级过滤、canonical_hash 去重、TaskRun、失败隔离。
- 规则摘要、实体/风险词提取、规则评分、证据引用。
- FTS5 优先、LIKE fallback 的搜索和多条件过滤。
- 收藏、专题、观察清单、保存搜索、提醒规则、站内消息。
- 本地词典翻译辅助；PWA 不再展示翻译维护模块，内部维护 API 保留。
- 同一事件规则归并和事件页；保留每条原始来源 URL。
- 本机运行闭环：启动时采集、后台定时采集、运行页状态、手动公开源采集。
- 手机远程骨架：Basic Auth + 用户自行配置的安全通道。
- 版本节点 `1.3`、数据保留说明、SQLite busy timeout/WAL 尝试、当前状态短文档。

未完成：

- B 站采集、OCR、字幕读取、音频转写。
- 微信类真实推送、Webhook 签名和重试。
- 登录态平台适配器。
- 语义检索、向量聚类、长周期事件链追踪。
- 系统服务化、Windows 开机自启、日志轮转、生产级 HTTPS 证书管理。

## 3. 下一阶段建议

### Goal A：本地大模型翻译接入

目标：在不破坏现有词典翻译和原文证据的前提下，新增可选本地大模型翻译 provider。

边界：

- 默认不依赖云 API。
- 未配置模型时系统继续用词典 provider。
- 不把译文覆盖原文、来源 URL 或证据引用。
- PWA 只展示自动翻译结果和失败原因，不恢复手工词典维护工作台。

### Goal B：RSSHub 来源状态诊断

目标：让数据源页或运行页展示每个 RSSHub route 的最近健康、最近采集数量、失败原因和建议处理。

边界：

- 不修改 RSSHub 源码。
- 不依赖真实公网测试通过。
- 401/403/429 时停用或提示，不规避限制。

### Goal C：OCR/字幕/转写接口

目标：在 Extractor 边界内先实现本地 fixture 验证，让 Asset 与 Extraction 可以在详情页展示。

边界：

- 没有外部模型或二进制工具时返回明确未配置状态。
- 单个媒体处理失败不阻断正文内容入库。

### Goal D：站内日报与外部推送准备

目标：在 Notifier 边界内实现站内日报汇总和 Webhook 签名/重试设计。

边界：

- 不直接接入真实微信账号或私密 token。
- 推送内容保留证据引用，不输出直接买卖建议。

### Goal E：大文件模块化重构

目标：降低后续 agent 读取成本，优先拆分 `sqlite.py`、`app.js`、`public_sources.py`。

建议顺序：

1. 把 SQLiteStore 的 API 组装、通知、词典维护拆成小 helper。
2. 把 PWA JS 按页面能力拆成独立静态模块，保持无构建工具。
3. 把公开源 adapter 的 RSSHub/HTML/JSON 解析 helper 拆分，保持 SourceAdapter 接口不变。

## 4. 长期守门规则

- 每轮新增能力必须保留原始 URL 和证据引用。
- 每轮新增外部来源都必须可配置关闭，并证明失败不影响其他来源。
- 不接登录态、Cookie、验证码、JS 渲染、浏览器自动化或反爬绕过来源，除非先单独设计安全边界。
- 不输出直接买卖建议。
- 不硬编码本机绝对路径、真实账号、Cookie、token 或隧道地址。
- 不把 fixture 绿色测试当成真实平台稳定承诺。
